System Overview

Purpose

Windrunner is a containerized utility designed to extract metadata from Harbor container registries, resolve platform-specific image configurations, and persist runtime parameters for downstream workflow execution within Kubernetes-based Argo Workflows.

Key Capabilities

Registry Integration

  • Connect to Harbor registry via REST API
  • Authenticate with configurable credentials
  • Fetch artifact metadata by project/repo/tag
  • Support multi-platform manifest resolution

Configuration Extraction

  • Parse container image configuration blobs
  • Extract WorkingDir, Cmd, and Args
  • Validate configuration compatibility
  • Persist to shared volume for workflows

Workflow Orchestration

  • Event-driven workflow triggering via webhooks
  • Multi-stage Argo Workflow execution
  • Volume management with lifecycle controls
  • Integration with MinIO, Keycloak, Git

Deployment Features

  • Docker containerized Python application
  • Kubernetes-native deployment model
  • Persistent volume claim management
  • Automatic cleanup and TTL controls

System Context

Windrunner operates as part of a larger Digital Forge platform ecosystem, serving as the initial stage in a multi-component workflow pipeline that includes:

  • Windrunner: Image metadata extraction and configuration preparation
  • Windbound: Artifact retrieval and S3 upload management
  • Windchest: Post-execution cleanup and result archival

Deployment Architecture Layers

Infrastructure Layer

  • Kubernetes cluster with Argo Workflows and Argo Events
  • Persistent volume provisioner (1Gi RWO volumes)
  • Container registry (Harbor) for image storage
  • Service mesh for inter-service communication

Platform Services

  • Harbor: Container image registry and artifact storage
  • MinIO: S3-compatible object storage for data
  • Keycloak: Identity and access management
  • Git: Source control and artifact versioning

Orchestration Layer

  • Argo Events: Event-driven workflow triggering
  • Argo Workflows: DAG-based container orchestration
  • Service accounts for RBAC control
  • Volume lifecycle management with GC strategy

Application Layer

  • Windrunner: Metadata extraction container
  • Windbound: Artifact fetching and S3 upload
  • Windchest: Cleanup and archival operations
  • Target containers: User workload execution

Error Handling

The system includes comprehensive error handling:

  • Configuration Validation: Raises NotImplementedError if Entrypoint is detected
  • API Failures: Harbor client should handle connection errors and authentication failures
  • Volume Errors: Directory creation failures will cause container exit with error code
  • Workflow Continuity: Main execution step has continueOn.failed = true to allow cleanup even on failure

Component Details

Windrunner Module Breakdown

main.py - Main Execution Module

Purpose: CLI entrypoint that orchestrates the metadata extraction workflow

Functions:

Function Parameters Returns Description
main() proj, repo, tag Boolean Orchestrates entire extraction flow from API calls to file persistence
check_for_unhandled_config() config: dict Boolean Validates config doesn't contain unsupported Entrypoint field
store_container_config() data: dict Boolean Writes WorkingDir, Cmd[0], and Cmd[1:] to volume files

Execution Flow:

  1. Initialize timing measurement
  2. Load environment configuration from env.py
  3. Create /mnt/vol/digitalforge directory if not exists
  4. Import Harbor client functions from windbinder
  5. Build artifact URL from parameters
  6. Fetch artifact metadata via Harbor API
  7. Resolve Linux-specific manifest digest
  8. Fetch configuration blob for that digest
  9. Validate configuration (no Entrypoint)
  10. Persist WorkingDir, Cmd, Args to files
  11. Print execution time and exit

env.py - Environment Configuration

Purpose: Centralize environment-derived configuration with sensible defaults

Configuration Variables:

Variable Default Value Description
VOLUME /mnt/vol Mount path where output files are written
HARBORHOST http://harbor-core.harbor/api/v2.0 Base URL for Harbor REST API
HARBORUSER admin Harbor authentication username
HARBORPASS Harbor12345 Harbor authentication password (should use secrets in production)

Purpose: Harbor API client wrapper (implementation details not in repository)

Expected Functions:

Function Purpose Expected Behavior

get_linux_digest(artifact_data) Extract Linux platform digest from manifest list Parses manifests array, filters for linux/amd64, returns digest
get_config(artifact_data) Extract configuration blob from artifact Retrieves config section containing WorkingDir, Cmd, etc.
